# 20260924.9 — CAD 成本实测（方向 3 暂缓）+ 评审可见性（版号 / 待审标记）

两件都发生在 20260924.8 之后：一件是把"CAD 到底多贵"量出来并据此决定暂不动它，一件是让页面自己把"改的是同一版""还差哪间没审"说清楚。

### CAD 一次重跑的真实代价（实测，真实 build123d）

| 阶段 | 耗时 |
| --- | --- |
| layout → `panel_plan` | 0.01 s |
| panel → `manufacture_plan` | 0.05 s |
| manufacture → `feature_tree` | 0.03 s |
| feature_tree → **CAD** | **4.8 – 5.6 s**（出 `model.step` ≈200 KB + `drilled-holes.{json,glb,step,step.glb}` + `bom.md` + 六面钻 XML） |

- **内容逐字节相同的第二版照样重跑 5.37 s**，产出的 STEP 与第一版**逐字节相同**（`e63ff928dfdaecba` 两次一致）——这次重跑纯属白跑。
- **耗时与柜数无关**：1 件 4.75 s、3 件 4.80 s、6 件 4.90 s；STEP 大小也几乎不变（200 / 200 / 200 KB，小柜 184 KB）→ 这 4.8 秒基本是**固定开销**（起进程 + 导入 build123d + 初始化发射器），不是几何计算。
- 顺带查清一条既有现状（文档已写明，不是新 bug）：`require_primary_handoff()` 取 `cabinets[0]`，所以制造 / 特征树 / CAD **目前只处理主柜**——这解释了上面的形状数据，也意味着"逐柜复用"的前提是"逐柜 CAD"。

### 决定：方向 3（产物按内容寻址）暂缓，但留了唤醒条件

- 4.8 秒/次不值得为它改血缘（`delivery_validated` 的谱系校验 + `manifest` 的 stale 标记 + 混合来源）。
- 唤醒条件写进 `references/backlog.md`「方向 3」，并在 **`TOOL.md`**（动 CAD 前必看的文件）里放了一段带数字的提醒：① 孔位/加工计算变重之后（现在几乎全是固定开销，孔位一旦真实建模，单次会明显上涨——**重算越贵，内容寻址越值**）；② 多柜下游落地之后；③ 单次 CAD 实测 > 30 秒或出现反复白跑。
- 复现脚本：`temp/measure_cad.py`、`temp/measure_cad_shape.py`（临时目录，不入库）。

### 评审可见性：把"同一版"和"待审"摆到牌子上

- 工作副本牌子带上**版号**：「第 4 版 · 草稿中 · 同一版 · 已调整 N 次」/「第 4 版 · 已有下游产物：改动会落成新一版」——`applyWorking(payload)` 现在读整个文档（版号也在里面），不再只读 `working`。
- 房间药丸给**还没审过的房间**加标记：文案后缀「· 待审」+ `data-pending="true"` + 两条 CSS（未选中琥珀色、选中时琥珀底）。"改一间只审一间"要看得见还差哪间。
- 测试同步：断言新的 `applyWorking(payload)` 形状与版号文案、`data-pending="true"` 与「· 待审」。
