# 20260924.8 — 页面接入编辑：工作副本（改同一版）+ 按权限渲染 + 撤销日志

上一批（20260924.4）把写接口做好了，但页面还是只读——拖动没接上。这一批接上，并把"一次摆放 = 一个意图"这件事在版本模型里说清楚（方案 H）。

### 工作副本：边界是下游产物，不是时间

- **还没有下游产物 → 原地改这一版**：`revision_number` 不变、`version`（内容摘要）变。一次摆放里的连续微调不再各占一版（此前每次拖动 +67 KB 与一个版号）。
- **已经有下游产物 → 追加新 Revision**：已经有东西依赖那一版了，再改就不是同一版。新版从空日志开始，父修订的 `stage_inputs` 照样带走。
- 下游一产出，工作副本**关门**：清空撤销日志 + 一条 `workflow` 事件（`Revision.close_working_copy()`）。
- 改到哪一间，**那一间的确认作废**（移出 `approved_rooms`）；不再"每间都审过"时，`layout.confirmed` 与 `approved_stages` 里的 `layout_plan` 一并撤回——不让"已确认"挂在一份改过的内容上。其余房间的确认不受牵连（P4 的"改一间只审一间"照旧）。

### 撤销日志（先只记，不接按钮）

- `revision.working_ops` 每条记**改动前的旧值**（不是"从头重放"）→ 丢最旧的几条只意味着"撤不到那么远"，不会让撤销错位（上限 500）。
- **日志不是审计**：下游一产出就清空；审计靠 `workflow` 事件行（"调整过 N 次""撤销过 2 步"看得见，细节不留）。
- 接口 `POST /api/project/{project_id}/layout/undo`（`{expected_version, steps}`）：只在工作副本开着时可用，逐条恢复旧值，**失败整体拒绝**，并留一条 `undo N step(s)` 事件（撤销会让"已经跟人说过"的内容变样，必须看得出来）。页面暂不放按钮。

### 按权限渲染 + 页面自己拿编辑权

- **能不能编辑由服务端按权限渲染**：本机来源（`may_edit`）给可编辑页，其余给只读页；`?mode=view`（分享形态）在本机也强制只读。**URL 参数不是权限**。
- 可编辑页进页面申请**编辑租约**、5 秒心跳、**闲置 5 分钟自动让出**（点一下拿回来）、离开页面归还；助手持有时显示「助手正在处理」+「收回编辑权」（沿用上一批）。
- 拖动 → `POST /layout/edit`（带 `expected_version` 与 `X-Edit-Lease`）；失败分四种说清：**423** 助手正在处理 · **409** 画面过期（区分"内容被改了"与"刚被确认"）· **403** 没有写权限 · **422** 这次改动本身不合法。
- 页眉三块牌子：身份（可编辑 / 只读预览 / 只读分享）、**工作副本**（草稿中 · 同一版 · 已调整 N 次 / 已有下游产物）、编辑权。

### 验证

- 365 项测试通过。更新了原先按"每次改动都新开一版"写的断言，并新增：原地改（版号不变、内容变、日志 +1）、有下游产物时开新一版并带走 `stage_inputs`、改到哪间哪间退回待审（其余保留）、本地渲染成可编辑 / 非本机只读 / `?mode=view` 强制只读、契约记录 undo 端点。
- 真服务 + 无头 Chromium 实测 **11/11**：本机打开是可编辑页、页面自己拿到编辑权、工作副本牌子显示「草稿中 · 同一版」；**真实指针拖动**后版号不变而内容摘要变、日志 +1、状态栏写「已保存（同一版，草稿中 · 已调整 1 次）」；`?mode=view` 页强制只读、牌子是分享、没有「收回编辑权」按钮；无 JS 报错。
- 实测中修掉一处自己引入的 JS 错误（`applyLease` 丢了 `#lease-badge` 的查找，导致租约牌子不更新）。
