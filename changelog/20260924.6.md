# 20260924.6 — 房间级确认：改一间只审一间

布局检查点原来是"整份布局一个布尔 + 一次确认"。有了页面写项目（20260924.4）之后，改一件家具的摆放就会把整个布局打回未确认——改次卧的床头柜不该让主卧重新审一遍。

### 确认粒度下沉到房间，但下游闸门没变

- `Revision.approved_rooms` 记"人看过哪几间"；`confirm_room(project, room_id)` 一次审一间，`pending_room_ids()` 说还差哪几间。
- **`layout.confirmed` 仍是唯一闸门**，只是变成"每间都审过"的**派生值**：全部审齐时才 `confirm()` 布局并进 `approved_stages`。panel / 制造 / CAD 的契约一个字没改。
- `confirm_stage(layout_plan)` 保留"一次确认全部"的老语义（等价于把剩下的房间一次审完），老流程与老测试不用动。
- 老项目文件没有 `approved_rooms`：那时 `confirmed: true` 是唯一记号，读作"每间都审过"。

### 没动过的房间，确认跟着走

- 新 Revision 里某间房的内容与父修订**逐字节相同**且父修订审过它 → 自动记入 `approved_rooms`，并在 `inherited_rooms[room_id] = {sha256, from_revision}` 留痕（与修订继承同一条 R2 规矩：沿用要回指真正点头的那一版）。
- 若这样凑齐每一间，**布局检查点当场成立**，不必再让人点一次头（例如只改了 `stage_inputs`、或改的是别处而房间没动）。
- 判据是逐字节比较（房间定义 + 已摆放包络），不看人的描述。

### 工具面与快照

- `furniture_confirm_stage` 新增可选 `room_id`（仅 `layout_plan`；给别的阶段用会拒）。
- 快照新增 `approved_rooms` / `pending_rooms` / `inherited_rooms`；页面布局文档新增逐间 `approved` 标记与 `pending_rooms`（页面显示留给后续接线）。

### 验证

- 340 项测试通过（新增 14 条）：审一间→布局仍未确认且下游不跑；全审齐才确认；`confirm_stage` 仍等价于全审；重复审同一间无副作用；未知房间被拒；已确认后再审被拒；改客厅→只有客厅待审、卧室沿用并留痕；**一间都没动→确认全部沿用、布局当场已确认**；被改的那间不会"沿用"自己的旧确认；老项目文件读作全审过；标记能过 store 往返；快照/页面文档字段正确；工具面按房间确认并拒绝给别的阶段带 `room_id`。
