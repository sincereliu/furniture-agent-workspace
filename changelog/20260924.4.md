# 20260924.4 — 页面写项目：一次 op 落成一个新 Revision（灰度）

这是"页面能不能写项目"的分水岭。在此之前写项目只有对话（`furniture_revise_layout`）一条路，页面是只读投影；用户改一厘米都要回来找助手。放开写入的同时收三条约束：**一次只改一件**（原子）、**必须带版本**（不许拿旧画面覆盖）、**默认关闭**（灰度开关）。

### 接口

- `POST /api/project/{project_id}/layout/edit`，body = `{op, item_id, expected_version, …op 字段}`；响应就是 `GET /layout` 那份文档（新 `revision_number` 与 `version`），页面可直接换上新包络。
- 三道门按顺序，任一不过都**不落盘**：① 本机来源（`may_edit`）→ 403；② 灰度开关 `FURNITURE_PROJECT_LAYOUT_EDIT=1`（不设就是关，`true`/`yes`/空一律当关）→ 403，理由里点名变量；③ `expected_version` 必须等于页面最近一次看到的 `version` → 不符 409，detail 带 `current_version`。

### 语义

- 成功 = **追加一个新 Revision**（不复用、不原地改），布局回到**未确认**——改过的内容没人点过头，不能继承上一位的确认位；未确认的布局不写冻结文件，下游想读也读不到。
- 父修订的 `stage_inputs` 原样带走（摆放变了、柜体构造意图没变）。
- 几何校验不过（越界、与别的件或障碍物干涉、遮挡门窗洞口）回 422，**一个 Revision 都不留**。
- `fill` 件（宽与偏移由墙上的空段算出）拒绝摆放类 op：改了也会被重算覆盖，与其静默丢掉不如明说。

### 代码位置

- 几何在布局包：`furniture_layout/project_edit.py` —— 把目标房间还原成"场景源"，复用房间场景编辑的 op 词表与应用器（`scene_edit.apply_edit`），再用 `plan_scene()` 重新摆放 + 准入（`footprint` / 净距是算出来的，不会留上一版的派生值）；不引入第二套字段白名单。
- 版本与生命周期在 workflow 包：`furniture_workflow/project_layout_edit.py` 是**唯一门面**（校验开关与版本 → 调布局包算几何 → 驱动 orchestrator 造 Revision 并落盘）。HTTP 层不自己开 orchestrator，`test_entrypoint_architecture` 钉住这条。

### 顺带修掉的已知缺口

- `revise()` / `revise_layout()` 原来不把父修订的 `stage_inputs` 传下去，导致"只改摆放"之后 `run_next()` 直接报 `panel proposal is incomplete; missing: n_doors, shelves, back_mount, …`（18 个字段）。现在与 `revise_stage_output()` 一致地带走 `stage_inputs`。

### 验证

- 313 项测试通过。新增 14 条：成功落盘且别的房间与别的件不动、`stage_inputs` 保留、确认位不继承且不写冻结文件、版本冲突 409 且零 Revision、越界 422 且零 Revision、未知件、op 白名单（`move` 带 `rotation_z_deg` 被拒）、`fill` 拒绝、远程 403、开关关闭 403、开关字面量只认 `1`、纯函数不改入参、重算无残留派生值。
- 真服务 HTTP 实测（临时项目，测完删除）：陈旧版本 409 带 `current_version`；正常改动 200 / rev 2 / `layout_confirmed=false` / 位置生效；拿旧版本重放 409（丢更新被挡住）；`move` 带 `rotation_z_deg` 422；越界 422；落盘 `revisions [1, 2]` 且 `stage_inputs` 保留；未确认布局**没有**新增冻结文件。
