# 20260924.1 — 内容版本改为内容摘要 + 内容指纹收敛到一个实现

页面每秒轮询靠 `version` 判断"要不要重画"，而 `version` 原本是 `revision_id:number:确认位`：同一 Revision 内原地改摆放时版本号不变，别的窗口和助手就察觉不到变化。同时 `layout_sha256` / `panel_sha256` / `source_sha256` / 交付包的 `_stable_digest` 各有一份摘要实现，同一份内容可能算出两个指纹。

### 内容指纹：只有一个实现

- 新增 `furniture_workflow/workflow_digest.py::stable_digest()`：对 `json.dumps(value, ensure_ascii=False, sort_keys=True, separators=(",", ":"))` 取 sha256。
- `workflow_constants._stable_digest` 改为它的别名；`workflow_project` 删掉 `_canonical_sha256`，`layout_sha256` / `panel_sha256` 改用它。
- 交付验证包（`furniture_delivery_validation.validation._stable_digest`）是同一算法在独立包里的副本，测试钉住两者一致。

### 内容版本

- `project_preview.py`：`version` 改为 `f"{layout_sha256}:{int(confirmed)}"`，并抽出 `layout_version(revision)` —— 轮询判断与写回的 `expected_version` 后来共用这一个字符串（见 20260924.4）。
- 版本语义写进契约：它是**内容版本**，不是"第几版"；`revision_number` 才是给人看的号。同一内容换个修订号不该看起来像变了，而"刚被确认"必须看起来变了。

### 兼容性

- 摘要统一后，新写出的 `layout_sha256` / `panel_sha256` 与旧值不同；旧冻结文件仍读得回来（下游读的是存下来的 `confirmed_panel_sha256`），旧文件成为孤儿——`store/` 已被忽略，属开发数据，不迁移。

### 验证

- 290 项测试通过。
- 新增 `test_content_digest_has_one_implementation`：四处实现对同一份含中文与嵌套的 payload 给出同一摘要。
- 版本断言改为内容摘要形式，并断言 `version` 里不含 `revision_id`。
