# 20261002.2 — 家具 id 入口校验（+ 旧工程迁移）、动作与台账自动对账

两件独立的小改，都在 [20261002.1](20261002.1.md) 之后：一件是**堵一个"建得成、跑到板件才炸"的坑**，一件是**让台账别撒谎**。

## 一、家具 id 的形状卡在入口

**问题（2026-10-02 写拆分设计稿时实测撞到）**：板件阶段拿家具 id 拼板件编号（`{cabinet_id}__{role}`，最终会成为生成源码里的标识符），所以它要求 id 是**合法 Python 标识符、不含 `__`**；而布局入口不校验——

```
admit_cabinet_id(None, fallback="cabinet-1")
→ ValueError: cabinet_id must be a Python identifier and must not contain '__'
```

于是 `cabinet-1` 这种 id **能建项目、能过摆放检查、能确认，到板件阶段才炸**。客户手上那个工程正是 `cabinet-1`。

**改法**：

| 落点 | 内容 |
| --- | --- |
| `furniture_layout/scene.py` | `ITEM_ID_PATTERN` / `PANEL_ID_SEPARATOR` + `require_item_id()`；在 `ItemSpec.from_dict` 处校验——全屋 / 单间 / 编辑**三个入口共用** `plan_scene`，一处收口三处覆盖 |
| 报错 | 点名是哪一件，并说清**为什么**（"the panel stage builds panel ids from it"） |
| 边界 | **只校验输入、不校验读取**：库里已有的旧 id 仍打得开（否则工程直接打不开，比原来更糟） |
| 一致性 | 阶段之间不互相 import，所以布局侧另写一条规则 → `tests/test_skill_architecture.py` 新增一条**跨阶段一致性测试**，同一批样本两边必须给出同样结论，改一边另一边就红 |
| 房间 id | **不受这条约束**（它只进 URL 与房间级确认，规则是 URL 安全的 `^[A-Za-z0-9_-]+$`）——所以 `room-1` 原样保留 |

**顺手发现的**：上面那条一致性测试**逮住了我**——我在 `scene.py` 注释里写了板件阶段的包名，而架构测试是**全文扫描**布局包（不只扫 import）。它是对的：布局阶段不该引用板件的内部实现，哪怕在注释里。已改措辞。

**旧工程迁移**（一次性脚本，**不入库**——仓库不迁移旧数据）：

```
改名: {'cabinet-1': 'cabinet_1'}
现在: ['cabinet_1']        working_ops 里的 id: ['cabinet_1']
```

几何不变（从场景源重建），撤销日志的 `item_id` 一起改（它是撤销日志不是审计，但改名后仍要能撤）；有房间级确认的工程会**中止**并让人重看，脚本不替人改确认。

**验证**：工具面实测 `cabinet-1` → 拒绝（`INVALID_ARGUMENT`，报错说清原因）、`cabinet_1` → 通过；迁移后的工程能重新规划（= 以后还能改）；预览页里已经是 `cabinet_1`。测试夹具里两处连字符 id 一并改成下划线（`test_room_level_confirmation`、`test_decision_log`）。

## 二、动作动了同一处，台账里的假设当场作废

**问题**：假设写"柜体沿北墙 **300** 居中"，客户早把它拖到 **340**，台账却还挂着"待确认"——**两边打架**，靠人手动划掉。

**规则**（三条都是"宁可不动作，也不误作废"）：

1. 只看**还待确认**的条目——客户点过头的约束是"改主意"的事，代码不许替他改；
2. 只看 `对象.字段` 这种**精确引用**（`cabinet_1.offset_mm`）；纯对象级的引用太模糊，不动它；
3. 字段必须**真的变了**——用"改前 vs 改后"比对，不看这次发的是什么 op（拖回原位不算改动）。

**实现**：

- `workflow_decisions.py` 新增三个纯函数：`parse_ref()`（拆 `对象.字段`）、`changed_item_fields()`（两次快照的真正差异，`fill` 跳过）、`stale_pending_ids()` + `auto_withdrawn_entries()`（挑条目 + 统一措辞）；
- 两条写入路径都接上：页面拖动（`edit_project_layout`）与助手改版（`furniture_revise_layout`），共用同一套规则；
- `speaker` 按当时的持锁者定：页面 = `customer`、助手 = `agent`；措辞写成"客户直接改了 `cabinet_1.offset_mm` 从 300 改成 448，与这条假设不一致，自动作废"（多处只列前三处，其余写"等 N 处"）；
- **看得见**：页面保存后的状态行带一句"顺带作废了 N 条助手假设（你改的与它不一致）"，写响应多一个 `withdrawn_decisions`。
