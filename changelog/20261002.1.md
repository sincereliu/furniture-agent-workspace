## 一、决策台账：客户说过的话进项目了

**为什么**：`layout_plan` 记的是**结果**，`working_ops` 记的是**改了什么**——两处都答不出"这句话是谁说的、我们把它落成了什么、他点头了没有"。三天后没人分得清哪一格是客户要的、哪一格是助手替他定的。原话此前只活在对话里。

**数据**：`Project.decisions[]`（挂在项目上、跨修订只追加）。每条 = `utterance`（原话）+ `interpretation`（落点）+ `speaker`（customer/relay/agent）+ `status`（assumption/confirmed/withdrawn）+ `source`（tool/page）+ `targets` + `applies_to` + `actor`（谁记的，运行时从编辑租约写）。

三条规矩，都是防"助手替他说话"变成事实：

1. **不冒充客户**：缺省 `speaker=agent`；要标客户说的必须显式写；
2. **不冒充已确认**：缺省 `status=assumption`，且**只有 `customer`/`relay` 能写 `confirmed`**——助手不能自己点头；
3. **改主意是加一条**：用 `targets` 指回被改的那几条，旧条目一个字不动；"此刻算不算数"由后续条目派生。

**准入一条路**：`workflow_decisions.py` 的 `admit_decisions()`（字段白名单、枚举、引用完整性——**校验在动项目之前**，不合法整批拒绝）+ `append_decisions()` 发号。
**踩到并修掉的一处**：原要求每条都有"原话"，但助手自己的假设没有原话可引，硬要只会逼出编造的引语 → 改成"从对话来的客户条目必须有原话，助手假设与页面按钮可以没有"。

**入口**

| 入口 | 用途 |
| --- | --- |
| `furniture_create_project` / `furniture_revise_layout` 的 `decisions` | 建/改布局时把这次的说法一起带上（可选） |
| **`furniture_record_decision`**（新工具） | **只记一句话，不动布局、不动阶段**（`progressed=false`）——客户后来说了一句、但还没到改布局的时候 |
| `POST /api/project/{id}/decisions`（新端点） | 页面上按「确认 / 划掉」：与布局编辑同一套门（本机 → 灰度 → `expected_version` → 编辑租约），另加"**只能动还待确认的那一条**"；**措辞由服务端写死**（`source=page`），页面递不进自由文本 |

**看得见**：页眉牌子「助手假设 N 条 · 点开确认」，展开每条显示"原话 → 落点"+「确认 / 划掉」（只读页只显示，并说明为什么不能按）。

**改动日志也有了"谁"**：`working_ops[].actor`（持锁者 / 标签 / 租约 id，读不出就写 `unknown`，**不猜**）。牌子「已调整 N 次」点开就是列表：`时间 · 谁（页面 窗口 xxxx / 助手 / 不知道谁）· 改成了什么`。

## 二、拖动：为什么"离墙的距离不对了"

用真浏览器 + 工程日志复现，日志第 4 条是铁证：**一次拖动把 2.4m 宽的柜子从北墙甩到 `y=2777`**（后面几次也都在几百到一千多毫米地跳）。两个问题叠在一起：

**根因 A：换算拿错了参照物。** 旧算法用"光标射线的地面交点"算位移。抓在家具**上半身**时，那条射线打到地面已经在很远处（接近地平线），鼠标动几个像素就能换出好几米。

- 修法：新增 [static/layout_drag.js](../domain/skills/layout-plan/scripts/furniture_layout/static/layout_drag.js) → `groundDragDelta()`，按**家具脚下那一点**的比例换算：横向走相机右向量，纵向走相机前方向并除以 sin(俯仰)（地面在屏幕上被压扁了这么多）。于是同样的手部位移，在任何抓取高度都走同样的距离。

**根因 B：掉下墙面就回不来了。** 向外拖过阈值即转成"自由摆放"，而自由件再拖回墙边只会**顶在墙上不动**——滑不动、也不再显示"靠墙"。

- 修法：同一个模块里的 `wallSnap()`：自由件**轴对齐且背面正好落在墙上**（容差 0.5mm、整件在房间里）时重新认成墙摆；斜着放的不吸附，离墙 2mm 的不吸附（不做"自动摆正"）。

**顺带两处**：落盘时 `mode` / `host_wall` / `offset_mm` **一律显式发**（模式互转不显式说，服务端会按它那边的旧模式解释——那正是"改完位置不对"的另一来源）；吸附那一帧把屏幕起点归零，不然同一段手部位移会被算两遍（表现是"吸附那一下多走一截"）。

**实测（真浏览器 + 真服务）**：抓在柜子上半身横向拖 12px → 修复后 **152mm**（`沿墙 550 → 600` 到东端夹住，再 `-12px → 448`，线性、对称），并且**自动变回「靠墙」**；修复前同样的手势可以到 2777mm。

## 三、时间显示：不是"现在的时间"
日志里存的是 **UTC**（对的：存绝对时间，换台机器看也准），但页面把字符串切一刀直接显示 → 显示成 UTC，比本地时间**早 8 小时**（本地 01:47 显示成 17:47）。

- 修法：页面按**看页面这台机器的本地时间**显示（`localTime()`，`new Date()` 转换后自己格式化，不依赖语言环境）。落盘格式没动。
- 验证：重启后同一面板显示 `2026-10-02 01:47`，当时本机 `01:51`。

## 四、收尾小修：`hidden` 被 CSS 盖掉

客户在页面上「划掉」了一条助手假设，**写是写进去了**（台账里 `dec_3` 作废 `dec_2`，`pending` 已空），但页面上**还留着一个空气泡**：`.basis-badge{display:inline-block}` 覆盖了浏览器默认的 `[hidden]{display:none}`——`hidden` 属性在"作者样式设了 display"时是失效的。

- 修法：加一条 `[hidden]{display:none !important}`，同时管住 `.working-badge` / `.lease-badge` / 两块面板这些自己设了 display 的块，也管住以后新加的；
- 测试：页面契约测试加一条，钉住这条规则在。

## 五、留档讨论：房间怎么"确认"（明天选一条，还没动手）

客户在页面上拖完柜子问："我挪动过柜体，如何确认？"——答案是**今天页面上没有确认入口**：拖动会落进工作副本并把**那一间的确认作废**（药丸上变「· 待审」），而"确认这一间"只能由助手在对话里调 `furniture_confirm_stage(project_id, room_id=…)`。

要确认的其实不是"他按了按钮"，而是**"这一版内容有人看过、没人提异议"**这个事实。按钮是最笨的一种获取方式（把"看"和"表态"拆成两步）。留档五个候选：

| | 做法 | 优雅在哪 | 代价 / 风险 |
| --- | --- | --- | --- |
| A | 加「确认这一间」按钮 | 直白 | 多一个要记住的步骤；改一下又退回待审，按钮意义会"闪" |
| B | **行内确认**：手一松（拖完/改完）就地一句「这一间就这样？」，10 秒不点自己消失、保持待审 | 确认发生在**刚做完事的那一刻** | 低（端点已有，一行 UI）；要防误触 |
| C | **集中确认**：说"下一步"时把**没看过的房间**列出来一次问清，一次点头 = 这批 | 折进本来就有的"推进"动作 | 必须先列出来再点头，否则批量掩盖"没看" |
| D | 让"看"自己成为证据（presence + 内容摘要，零动作） | 零动作 | **静默通过**，违背"别让人以为少做了一步"的原则；单独用不行 |
| E | **并进决策台账**：一间确认 = 账里一条确认记录（带当时内容摘要），"待审"变成派生状态（当前内容没有对应确认记录） | **不新增概念**：同一本账、同一个端点、同一套可撤销语义；撤销不用写代码 | 动地基：`approved_rooms` / `inherited_rooms` / 布局检查点都要改 |

**建议**：短期 **B + C**（不加按钮，只在"刚改完"和"要推进"两个自然时机收口，并把"哪些还没过"继续摆在药丸上）；中期若确认这套要重构，走 **E**（不再加第三种状态）。D 的"留痕"部分值得单独做：把"这一间什么时候起没动过、谁打开过"写进交付清单。

登记在[编排与生命周期未落地需求](../domain/skills/cad-generated/references/backlog.md)。
