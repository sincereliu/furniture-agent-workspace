# 20260924.5 — 修订继承：内容没变的下游产物不再让人重新确认

上一批让"页面改一次摆放"变便宜，但只要每次改完还要人重新确认板件、重跑下游，这个便宜立刻被吃掉：板件内容与摘要明明一样、冻结文件就是硬盘上那一份，新 Revision 的 `confirmed_panel_sha256` 却是 `None`。而契约本来就写死了——布局交给板件的只有 `id / furniture_category / width / depth / height`，房间、摆放、原点、旋转不属于这个契约。

### 判据（与板件读的字段同源）

- `workflow_inheritance.py::envelope_set()`：`{柜 id: (类别, 宽, 深, 高)}`，投影直接建在 `panel_envelopes_from_layout()` 上——判据看的字段与板件读到的字段不可能分家。
- `envelope_diff()`：分类出 `same / added / removed / resized / recategorized`，用来向人解释这次到底改了什么。

### 承认与留痕

- `workflow_stage_runner._inherit_settled_stage()`：阶段产出落定后，若**更早的某个 Revision 上该阶段已确认、且确认的内容摘要与本版逐字节相同**，就把本阶段就地记为已确认（板件同时写 `confirmed_panel_sha256`），不再要求人点一次头。
- `Revision.approved_digests[阶段]`：`confirm_stage()` 写入，记"人当年点的哪份内容"；`Revision.inherited[阶段] = {sha256, from_revision, from_stage}` 留痕并追一条 `workflow` 事件。老项目文件没有 `approved_digests` 时，板件回退读 `confirmed_panel_sha256`。
- 契约明确：`approved_stages` 的语义是**「这份内容已被确认过」**，不是"人在这一版又点了一次头"；审计靠 `from_revision` 回指真正点头的那一版。

### 让人看得见（R3）

- `project_snapshot()` 增加 `inherited` / `inherited_stages`，页面布局文档也带 `inherited`——别让"系统少做了一步"变得看不见。

### 与设计稿的一处偏离（已写进契约）

- 设计稿原本写"命中判据就直接用已有产物、不重算"。实现改为：**判据只用来解释，承认靠内容摘要逐字节比对，重算照跑**。理由是重算本身毫秒级，而"跳过重算"会把隐藏依赖的风险引进来——万一某阶段偷读了布局的其它字段，判据会把"变了"误判成"没变"，短路就错得无声无息。现在判据错了也继承不了（摘要不同）。
- 另一条边界：只在**逐字节相同**时继承，不做近似、不做容差。

### 验证

- 326 项测试通过。新增 13 条：判据分类、`fill` 件随墙长变宽必判"变了"、首版没有可继承对象所以不自我点头、快照与页面文档可见、留痕能过 store 往返。
- 逐字节不变式（设计稿点名的最大风险）：改摆放 → 板件输出**逐字节相同**；改房间尺寸 → **相同**；改柜宽 / 落地柜变吊柜 / 加一件柜 → **必变**；`fill` 件 + 房间变宽 → **必变**。
- 真 store 端到端：首版确认 → 只改摆放跑板件（`inherited=['panel_plan']`，**没让人确认**）→ 直接 `run_next` 走到制造段（`manufacture_plan` 输出存在，`inherited` 回指 rev_1576b32a）→ 改柜宽跑板件（`approved=['layout_plan']`、`confirmed_panel_sha256=None`，必须重新确认）。

### 未做

- 方向 3「产物按内容寻址复用」：`generated/<project-id>/revision-<n>/` 仍按修订号出目录，所以 CAD / STEP 仍会重跑（哪怕几何一模一样）。要改得动 `delivery_validated` 的谱系校验与 `manifest` 的 stale 标记。
- 逐柜复用（卧室沿用、客厅重算）与制造/特征树那两级"免确认"的确认文案。
