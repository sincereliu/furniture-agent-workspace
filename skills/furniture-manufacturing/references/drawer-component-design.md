# 抽屉组件级实体需求（记录）

状态：**需求记录**（未立项、未实施）。来源于 2026-08 抽屉滑轨 Connector 化（档 A）讨论。

## 背景

抽屉本质是**子装配组件**，不是散板：

- 有自己的板件集合（前板/左右侧板/底板，可选背板/导轨条）、盒体拓扑、五金（滑轨、拉手）；
- 尺寸链只有作为组件才自然：抽屉宽 = 柜体开口宽 − 2×滑轨安装余量（三节轨侧装 12.5mm/侧）− 公差；抽屉深 = 柜体深 − 背板 − 前间隙；抽屉高 = 可用高 ÷ 层数 − 层间间距；
- 滑轨长度由抽屉**自身深度**决定、承重由抽屉宽度决定——因此不能从柜体面板"猜"。

## 现状

- 板件规划阶段**不生成任何抽屉板件**（`furniture-panel-planning` 无 drawer 代码）；
- 因此 BOM 的滑轨分支此前永不触发，`match_drawer_slides` 曾是死路径；
- layout 的 `drawer_count` 仅出现在测试数据中，无消费方（疑似无效字段，需清理或启用）；
- 档 A 已完成：`DrawerSlideConnector`（`connectors/drawer_slide.py`）按下方契约实现并注册 `ALL_CONNECTORS`，`manufacturing_hardware.py` 死代码已删除。**制造阶段滑轨自动生效的前提 = 板件规划产出抽屉板件。**

## 契约（档 A 已按此实现，档 B 必须遵守）

1. **panel_type 命名**：抽屉板件 `panel_type` 含 `"drawer"`（如 `drawer_front` / `drawer_side` / `drawer_bottom`），`DrawerSlideConnector` 以此识别。
2. **尺寸来源**：抽屉深度 = 抽屉板件 `size_y` 最大值，宽度 = `size_x` 最大值——取自抽屉板件自身，不依赖柜体面板。
3. **实例粒度**：抽屉板件 `label` 形如 `drawer_<角色>_<实例后缀>`，实例 key = label 最后一个 `"_"` 分段（沿用动态板件命名，如 `shelf_z999` → `z999`）；数量 = 每抽 1 副（左右各 1）× 抽屉实例数，不同规格（长度/承重）分条记录。

## 需求

1. **抽屉组件物化**（板件规划阶段）：抽屉子拓扑 + 尺寸链 + 装配偏移，生成抽屉板件（必须满足上述契约，滑轨即自动进 BOM）。
2. **Layout `drawer_count`**：启用为真实输入（抽屉层数/数量），或清理为无效字段——二选一，避免"收了不生效"的静默失效（参考铰链死接口清理决策）。
3. **校验**：滑轨长度 ≤ 抽屉深度 − 50mm；安装余量（侧装 12.5mm/侧、底装 12.7mm）不超开口。
4. **五金变体**：隐藏轨/品牌选择待组件落地后由配置注入（当前单一默认三节轨，与铰链精简为单一默认同思路）。

## 实施建议

- 属跨阶段改动（布局/板件规划/制造），单独立项评审后再动；
- 与 `connection-point-design.md` 同属"组件/实体层"演进：系统需要"柜体之下、板件之上"的中间实体层，届时所有 Connector 的输入形态统一适配（面板 → 面板+组件），不必在档 A 超前设计组件接口。
