# 抽屉变体契约

回答“抽屉的滑轨系统与抽面归属怎么表达、换一种做法以后出哪几块板？”；本文件是抽屉变体的唯一规则中心，[抽屉尺寸链](drawer-dimension-chain.md) 只讲毫米怎么来。

**状态：P1 已落地**（`drawer_runner` / `drawer_face` / 三条净空字段 + 组合准入 + 角色表 + 件数校验）。物化分七步，见文末「分期」；**除 P1 外都还没做**，准入会拒绝还没物化的组合。

## 一、两个轴，不是两个类型

| 轴 | 取值 | 决定什么 |
| --- | --- | --- |
| `drawer_runner` | side_mount 三节轨 / undermount 托底轨 / metal_box 骑马抽 | 盒体包络怎么算、出哪几个角色、五金形态 |
| `drawer_face` | box_face 盒体前板兼前脸 / applied 独立抽面 | 多不多一块抽面（`face`） |

两个轴正交，但有一条组合**物理上不成立**：骑马抽的左右侧板是金属五金，木件只有底板、背板与抽面，所以 `metal_box` 必须配 `applied`，准入直接拒 `metal_box + box_face`。

**内抽（藏在门后、没有可见抽面）不是这两个轴的一种**：它改的是深度方向的前部占用（门厚 + 门后缝），等混合分区（P6）再进来，不要塞进 `drawer_face`。

## 二、角色表与件数

件数不是常数，是 (runner, face) 的函数。角色 → 板件类型 → 材质角色：

| 角色 | `panel_type` | 材质 | 三节轨·兼任 | 三节轨·独立 | 托底轨·兼任 | 托底轨·独立 | 骑马抽 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `face` 可见抽面 | `drawer_face` | 门板色 | ＝`box_front` | ✓ | ＝`box_front` | ✓ | ✓ |
| `box_front` 盒体前板 | `drawer_front` | 柜体板 | ✓ | ✓ | ✓ | ✓ | — |
| `box_side_l/r` 侧板 | `drawer_side` | 柜体板 | ✓ | ✓ | ✓ | ✓ | —（五金） |
| `box_back` 背板 | `drawer_back` | 柜体板 | ✓ | ✓ | ✓ | ✓ | ✓ |
| `box_bottom` 底板 | `drawer_bottom` | 柜体板 | ✓ | ✓ | ✓ | ✓ | ✓ |
| **木件数** | | | **5** | **6** | **5** | **6** | **3** |

两条命名约定，别改：

- `box_front` 沿用旧词表 `drawer_front`（老冻结文件钉着它），“前脸是不是独立的一块”由 `face` 角色与 `front_id` 表达，不靠新类型；
- 板件 id / role 仍是 `drawer_<角色>_z<起点>`，制造按 label 末段分抽屉实例。

## 三、尺寸链：三条真源分开写

```
开口：W 内宽、H（底板上表面→顶板下表面）、D（背板内表面→柜前沿）

【前脸】正面排版给
  Fh = H − drawer_bottom_clearance − drawer_top_clearance
  抽面高 = (Fh − (n−1) × drawer_layer_gap) / n
  抽面宽/起点/覆盖 = 排版结果（今天是内嵌口径，覆盖式留到排版落地）

【盒体包络】抽屉自己算，数值来自工艺卡
  盒宽 = W − 2 × drawer_side_clearance
  盒深 = D − 前部占用 − drawer_back_clearance       # 外抽：前部占用 = 抽面厚
  盒高 = 抽面高 − 2 × overlap                        # 底抽全盖，其余 0
  盒内 z0 = 盒底 + drawer_bottom_raise               # 托底轨才不为 0

【角色尺寸】只引用包络的命名量，不自己减板厚
  box_side   = 侧板厚 × 盒深 × 盒高
  box_back   = 内宽   × 背板厚 × 盒高
  box_bottom = 内宽   × 内深   × 底板厚
  骑马抽     = 内宽 = 标称 − 2 × 金属侧板厚（底板、背板同取内宽）
```

**命名量（`outer_w` / `inner_w` / `outer_d` / `inner_d` / `h` / `inner_z0`）是硬要求**，不是为了好读：骑马抽的“侧板厚”是五金参数、不在 `board_thickness` 里，写死“减板厚”就表达不了。

三条缝的归属别混：**抽面的上/下/层间归正面排版**，**盒体的左/右/后与底板上移归抽屉自己**。同一个“间隙”分给两个真源，是为了不让正脸对位和盒体配合互相改数。

## 四、字段与缺省

| 字段 | 缺省 | 含义 |
| --- | --- | --- |
| `drawer_runner` | side_mount | 滑轨系统 |
| `drawer_face` | box_face | 抽面归属 |
| `drawer_top_clearance` | 0 | 顶层抽面上沿 ↔ 顶板下表面 |
| `drawer_bottom_clearance` | 0 | 底抽下沿 ↔ 底板上表面 |
| `drawer_bottom_raise` | 0 | 底板底面 ↔ 盒体底面（托底轨轨腔高度） |

- **缺省 = 今天唯一的做法**，所以缺省不落盘：`spec` 里不会出现这些键，老工程产出逐字节不变。
- 五个字段都写在同一个阶段：**只在 `drawer_count>0` 时成立**，没有抽屉却写变体直接拒（别让冻结文件带着用不上的口径）。
- 三条净空是**板件的几何事实**，不是五金参数：五金（`hardware_catalog.yaml` 的 `drawer_slides`）只做兼容校验（例如轨的安装高度 ≤ 轨腔高度），板件阶段不读制造目录。换轨要能体现为“板件变了”，而不是制造偷偷改孔。

## 五、准入规则（已经在跑）

1. 枚举只认规范值，不做同义词、不把别名归成规范名。
2. `metal_box + box_face` 拒（物理上没有那块木前板）。
3. **物化闸门**：组合不在 `drawer_variants.MATERIALIZED_VARIANTS` 里拒；三条净空非 0 也拒。拒的是“字段收了、几何没做”，不是“客户要求不支持”——所以话术要说明还没做，而不是说做法不存在。
4. `drawer_count = 0` 时写任何变体字段都拒。
5. 件数校验从角色表读，不再写死“每抽 5 块”。

## 七、分期

| 期 | 放开什么 | 产出变化 |
| --- | --- | --- |
| **P1 已落地** | 字段、组合准入、角色表、件数校验 | 无（缺省不落盘） |
| P2 | 尺寸链重写：上/下缝显式、底抽缝不再双倍 | **一次基线重生成**（毫米级） |
| P3 | `applied` 独立抽面（多一块 `drawer_face`） | 仅新组合 |
| P4 | `undermount`：换间隙/后缝/轨腔 + 盒内 z 基准链 | 仅新组合 |
| P5 | `metal_box`：3 木件 + 标称档 + 五金一套 | 仅新组合 |
| P6 | 混合分区：腔级挂载 + 前脸迁进评估器 + 内抽 | 仅新组合 |

P2 之后的每一步只放开一条：`MATERIALIZED_VARIANTS` 加一条、尺寸链把对应公式补上、校验加一条不变量。

## 八、下游要点

- **盒体包络要进冻结文件**：制造不能再用“抽屉板件尺寸的最大值”当盒深/盒宽——有独立抽面时最大值是抽面，骑马抽更是推不出来。
- **接触为空是合法的**：骑马抽的底板、背板各自嵌进金属侧板，木件之间不互相顶，所以 0 条接触、0 套三合一；校验不能要求每抽都有连接。
- 滑轨/骑马抽五金按**组件包络**选型（长度、承重档、标称），不按板件猜。
