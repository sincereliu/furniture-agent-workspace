# 柜内结构 → 板件：单一来源与物化清单（设计决定）

回答"评估出来的毫米怎么变成板件"。前置：[柜内结构契约](interior-structure-contract.md)（人只说三件事，尺寸由程序算）。本文只定接口与分期，**不含 A/B 凑整口径**（那是车间决定，见文末）。

## 决定 1：单一来源——谁拥有哪些数

**归属口径已经定过**：[板件阶段 SKILL](../SKILL.md)「把客户的话收成整份板件方案」一节写着"门宽、缝、区间、净空和段长以 `furniture_evaluate_interior` 的回报为准"。本节只是把它铺成一张表，供物化时对照，**不另立一套**。

| 数 | 谁拥有 | 谁消费 |
| --- | --- | --- |
| **门**：每扇宽、每扇起点、逐条缝宽、缝中心、左右边距、`pairs` | **评估器**（`evaluate_interior`） | 板件（出件）、审查清单、中立板锚定 |
| **中立板**：区间（由缝 + `seam_align` + 板厚算） | **评估器** | 板件（出一块竖板）、各腔边界 |
| **分段**：各段长度（由断口 + 板厚算） | **评估器** | 板件（分段成件） |
| **各腔净空**：**只有净宽**（评估器只算宽度方向；高与深归层板、用途规则） | **评估器** | 判定（内容放不放得下）、审查清单 |
| **内容**：层板 / 抽屉 / 挂衣 / 空 | **提案**（腔级，阶段 2 落地） | 板件 |
| **包络**：id / 落地还是吊柜 / 宽 / 深 / 高 | **布局**（不动） | 评估器与板件 |
| **深度方向**的 `front_gap`、料厚、踢脚高、抽屉尺寸链 | **已准入的提案/料档** | 板件（沿用现状） |

**规则**：板件阶段**不再自己算门宽与缝**（今天 `topology_solver._door_panels` 自己算一套，与评估器形成两套公式）。有 `interior` 时**以评估器输出为准**；没有 `interior` 时走老路径。

**现在到哪一步**：**中立板和门宽都已经按这条走**——`dividers` 只提交缝与锚法，区间由 `construction_geometry.divider_interior_report` 向评估器取；门的宽度与起点由 `door_interior_report` 取，`_door_panels` 已经不再自己算 `(柜宽 − 边距×2×扇数)/扇数`。**分段（`breaks`）还没做。**

**校验分工**：

| 判什么 | 谁判 |
| --- | --- |
| 合不合理（锚、缝、净空够不够、段太短、凑整） | 评估器（`findings`：`blocked` / `assumption` / `unjudged` + 两侧代价） |
| 几何自洽（板件不重叠、依赖闭环、拼得出来） | 板件阶段（沿用现有校验） |
| 能不能做出来（料、孔、五金、加工） | 制造及以后（不动） |

## 决定 2：物化清单与分期

| 批次 | 物化什么 | 依赖 | 验收 |
| --- | --- | --- | --- |
| **0** | **先确认回归基线**（`test_panel_output_baseline.py`）：老输入产出已冻结，动板件前跑一次 | 无 | 基线绿；红了先判意外还是故意 |
| **1** | **中立板**（一块竖板：尺寸/位置/依赖）—— **已落地**；**分段板**（顶板/底板/踢脚/背板 → 多段各自成件）—— **未做** | 评估器输出区间与段长 | 中立板：`test_panel_divider.py`；没有中立板的老输入逐字节不变。分段：契约第 1 节的四种组合都能出件 |
| **2** | **多门**（>2 扇，按扇序出件）+ **门板铰链侧** `door_hinge_side`（对开由几何定）—— **已落地**；铰链**孔位**仍在制造 —— 未做 | 撤掉"`n_doors` 大于 2"的停问；板件按评估器的扇序出件；铰链侧随门板进冻结文件 | `test_panel_multi_door.py`、`test_door_hinge_side.py`：2400/7、1211/4、1511/6 能出件，2500/5 能配 3 块立板；**基线因新增 `door_hinge_side` 重新生成过**（见下） |
| **3** | **按腔内容**（每腔自己的层板/抽屉/挂衣） | 内容从柜级升到腔级（与组件化合并） | 混合分区（左挂衣右抽屉）能出件 |

**板件 id**：**沿用现有角色名**（门是 `single_door` / `left_door` / `right_door`，被 `test_panel_rule_contracts.py` 钉着；其余板件也是角色名 + 柜 id 前缀）。多扇、分段需要区分时的序号命名，**由实现与对应测试一起定**，本设计**不另立一套**——先把形状做出来，命名跟着现有习惯走。

## 审查清单（前半已落地）

`format_interior_review_markdown(report)`（`panel_review.py`）把评估器的回报排成给人核对的清单：正面（扇数 / 每扇宽 / 成对门 / 逐条缝 / 左右边距）、中立板（对齐 / 锚 / 区间）、腔（净宽 + 判定）、分段（段数 / 各段长 / 断口宽）、findings（状态 + 继续与停下的损失）。工具 `furniture_evaluate_interior` 的回报里带 `interior_review`——**直接展示它，不要自己拼格式**。

两条约定：

- 清单写明"这是评估结果，还没写进板件"，免得被当成板件表；
- 评估器只算**宽度**：腔高、腔深由层板与用途规则另算，清单不编。

凑整口径保持中立：某条缝 ≠ 2×边距 → 标"吸收凑整零头"；左右边距不等 → 标"零头在边距"。A/B 两种都显示得出来，口径定了不用改这里。

后半（板件表按腔 / 段分组）等批次 1 物化之后。

## 决定 3：不变量（改这个不许破）

1. **产物契约不变**：板件 id / 角色 / 尺寸 / 位置 / 依赖 / 接触（大面–端面）形状不动 → 制造、特征树、CAD、交付**无感**；
2. **布局不动**：包络仍是五个字段；
3. **老输入逐字节不变**：没有 `interior` 的工程走老路径，产出与改动之前一致（回归条件）。
   **唯一的故意例外**：门板现在带 `door_hinge_side`（对开由几何定），四份基线摘要因此重新生成过——
   已核对"把这个字段递归摘掉后逐字相同"，理由写在 `test_panel_output_baseline.py` 头部；
4. **缺数据停问**：净空/段宽判定没有 `confirmed` 数据时，给 `assumption`/`unjudged`，不拿典型值冒充；
5. **继承判据不动**：仍按包络五个字段判"内容变没变"；板件内部结构变了会体现为该台重算，这是应然。

## 决定 4：A/B 中立（凑整口径明天定）

- 把凑整差异**关在评估器的一个函数里**（`_layout_doors`），外部看不见；
- 物化只消费输出（每扇宽 / 起点 / 缝 / 中心 / 左右边距 / 区间 / 段长）——**接口在 A、B 下相同，只有数值不同**；
- 契约文字写成两头都成立："**缝基值 = 2×边距；某条缝可因吸收凑整差而偏离基值**"；
- 测试分两组：**结构类**（区间/净空/分段，A/B 通用）+ **凑整类**（A 或 B 各一组）→ 明天定了只换第二组。
