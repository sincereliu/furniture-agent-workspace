# 连接与接触：默认规则表

回答“`compute_joints()` 算出的两条板之间的**接触**，哪些默认产生**连接**，哪些默认只是**接触**（不连接）？”。

本文件是**默认规则表**，不是固定判据。每条默认都可被用户对单个连接点显式覆盖（连接开关）。

## 两个概念

| 概念 | 含义 | 谁决定 |
| --- | --- | --- |
| 接触（joint） | 两块板几何上贴合：female 的面被 male 的端面顶住 | `compute_joints()` 纯几何推导，客观事实 |
| 连接（connection） | 该接触是否要固定 | 提案层给默认 + 用户开关 |

接触是几何事实，连接是工艺决策。二者分开：几何归代码，连接默认值归提案层、最终归用户。

**本表只回答“连不连”，不回答“用什么五金连接”**。五金件（三合一/螺钉/木榫/二合一/隔板钉…）是连接确定之后、由结构与用户选择决定的另一层决策，不落入本表。

## 连接开关（结构化字段）

`PanelJoint` 增加连接开关，值为三态：

- `on`：强制连接；
- `off`：强制不连，只是接触；
- `auto`：未定，由本默认规则表推导。

制造阶段只认开关结果，不再按轴方向（`edge_axis`）、板件名或“有无偏心轮面”猜“连不连”。

## 默认规则（auto 的推导）

对每条接触，按下面的顺序判定，命中即停：

1. **跨装配接触 → `off`**：female 与 male 分属柜体/抽屉两个不同装配（`compute_joints` 已排除，规则层兜底）。
2. **非固定贴合/靠接 → `off`**：
   - 固定层板 / 横板后端面搭在背板前面（female 是背板，`panel_type == "back"`）；
   - 背拉条与背板之间的面-面贴合。
3. **其余结构接触 → `on`**。

> 连接与否**不按轴方向判定**，也**不按“male 有没有偏心轮安装面”判定**。轴方向只决定“沿哪根轴固定”；偏心轮安装面只属于“三合一这种五金件”的可执行前提，与“连不连”无关。

## 默认结果对照（按当前柜型实测整理，待你复核）

| 接触（female ← male） | 默认 |
| --- | --- |
| 侧板 ← 顶板 / 底板 / 固定层板 | `on` |
| 侧板 ← 背拉条 | `on` |
| 侧板 ← 踢脚 | `on`（踢脚组件化后另议） |
| 顶板 ← 背拉条 | `on` |
| 踢脚板 ← 踢脚支撑 | `on`（踢脚组件化后另议） |
| 抽屉内部（前/后/底/侧板互贴） | `on` |
| 背板 ← 固定层板（层板后端搭背板） | `off` |
| 背拉条 ← 背板（面-面贴合） | `off` |

## 待确认项（你查看后定）

1. **踢脚组件化**：踢脚相关接触（侧板←踢脚、踢脚板←踢脚支撑）默认 `on`，但踢脚将独立成组件，此部分暂不深入，待组件化设计时再定。
2. **抽屉的连接结构**：抽屉内部接触默认 `on`，具体连接结构（对应不同五金与方向）待你补充口径，本表不按方向固定 x/y/z。

## 边界

- 这是默认规则，不构成死判据；用户可对任一接触点说“这个也要连/不连”覆盖为 `on`/`off`。
- 连接可沿 x/y/z 任一轴（端面方向由几何决定）；默认规则不按轴方向区分连接与接触。
- 铰链、二合一/隔板钉、滑轨、内嵌背板三合一分别由各自 Connector 负责，不落入本表。
- 本表只声明“连不连”的默认口径；五金类型与孔位几何（定位、`connection_id` 配对）归制造阶段，另行确定。
