# 连接与接触：默认规则表

回答“`compute_joints()` 算出的两条板之间的**接触**，哪些默认产生**连接**，哪些默认只是**接触**（不连接）？”。

本文件是**默认规则表**。几何接触归代码；默认连不连也由代码按本表解析到每条 `PanelJoint.connection`。

## 两个概念

| 概念 | 含义 | 谁决定 |
| --- | --- | --- |
| 接触（joint） | 两块板几何上贴合：female 的面被 male 的端面顶住 | `compute_joints()` 纯几何推导，客观事实 |
| 连接（connection） | 该接触是否要固定 | 本表解析为 `on`/`off`，写入 `PanelJoint.connection` |

接触是几何事实，连接是工艺决策。二者分开：几何归代码，默认连接归本表。

**本表只回答“连不连”，不回答“用什么五金连接”**。五金件（三合一/螺钉/木榫/二合一/隔板钉…）是连接确定之后、由制造阶段决定的另一层决策。

## 已落地

运行时在生成板件后解析每条接触，写出 `connection: on | off`。旧序列化没有该字段时按 `on` 加载，以保持历史行为。制造阶段先看 `connection`，`off` 的接触不再进入打孔/五金；轴方向和 `cam_face` 只用于选择三合一这类五金，不再用来猜连不连。

本轮**没有**逐条 `on/off/auto` 提案覆盖字段。用户若要改某条连接，只能通过后续契约扩展或整阶段 `revise_stage_output()`；不要假装现在就能提交开关。

## 默认规则（生成时的推导）

对每条接触，按下面的顺序判定，命中即停：

1. **跨装配接触 → `off`**：female 与 male 分属柜体/抽屉两个不同装配（`compute_joints` 已排除，规则层兜底）。
2. **非固定贴合/靠接 → `off`**：
   - 固定层板与背板之间的搭接（层板后端搭在背板前面）；
   - 背拉条与背板之间的面-面贴合。
3. **其余结构接触 → `on`**。

> 连接与否**不按轴方向判定**，也**不按“male 有没有偏心轮安装面”判定**。轴方向只决定“沿哪根轴固定”；偏心轮安装面只属于“三合一这种五金件”的可执行前提，与“连不连”无关。

## 默认结果对照

| 接触（female ← male） | 默认 | 状态 |
| --- | --- | --- |
| 侧板 ← 顶板 / 底板 / 固定层板 | `on` | 已落地 |
| 侧板 ← 背拉条 | `on` | 已落地 |
| 侧板 ← 踢脚 | `on` | 已落地；踢脚组件化后另议 |
| 顶板 ← 背拉条 | `on` | 已落地 |
| 踢脚板 ← 踢脚支撑 | `on` | 已落地；踢脚组件化后另议 |
| 抽屉内部（前/后/底/侧板互贴） | `on` | 已落地；具体五金与方向归制造 |
| 背板 ↔ 固定层板 | `off` | 已落地 |
| 背拉条 ↔ 背板 | `off` | 已落地 |

## 未做

1. **逐条覆盖**：没有 `auto` 请求字段，也没有按 `(female_id, male_id)` 提交 `on/off` 的提案入口。
2. **踢脚组件化**：踢脚相关接触目前默认 `on`，独立组件设计时再定。
3. **抽屉连接结构**：抽屉内部接触默认 `on`，具体五金与方向不由本表固定。

## 边界

- 制造阶段只认已解析的 `connection`，不再按轴方向或板件名猜“连不连”。
- 铰链、二合一/隔板钉、滑轨、内嵌背板三合一分别由各自 Connector 负责，不落入本表。
- 本表只声明“连不连”的默认口径；五金类型与孔位几何归制造阶段。
