# 空间 → 单元：拆分设计（设计稿）

回答"一块空间怎么变成 N 台可制造的柜子"。**状态：设计稿，未实现**；口径登记在 [未落地需求](backlog.md)「空间 → 单元：拆分求解器与约束词表」，前置是[多柜下游与逐柜参数](../../cad-generated/references/backlog.md)。

一句话：**空间是输入侧的源，单元是输出侧的事实，组是两者之间的一层关系。** 这份稿子把这三样各自的身份、边界和 id 规则定死，实现照着做。

## 一、身份不变式（先定死，后面所有取舍都从它推）

| 概念 | 是什么 | 谁拥有 | 下游看得到吗 |
| --- | --- | --- | --- |
| **包络 / 单元** | 一台可制造的柜子（一对侧板、独立打孔、独立包装） | 布局层的 `rooms[].items[]` | **只看得到它**（板件只读 `id / furniture_category / width / depth / height`） |
| **空间** | 一块区域 + 约束 + 锚（"北墙这 2400 做柜子"） | 布局层的 `rooms[].spaces[]` | 看不到 |
| **组** | 一排柜子的**关系**（对齐、踢脚、门缝一致） | 布局层（`group_id`） | 看不到（只用于展示、整排检查、交付汇总、血缘聚合） |

**三条不变式，都要有测试钉住**：

1. **下游只读单元**：板件/制造/特征树/CAD/交付一个字段都不该读 `spaces` 或 `group_id`；
2. **空间/组变了、单元五个字段没变 → 下游内容逐字节不变**（复用今天的[继承判据](../../cad-generated/references/revision-inheritance-design.md)）；
3. **单元 id 只增不改**（见 §三）：插入或删除一格，不许让别的单元换 id。

**明确不做**（都是"另一个问题"，别混进来）：

- 把"组"做成包络身份（一个包络 → 板件阶段再拆 N 台）：动血缘、动身份，收益是负的；
- 单体柜内部的竖隔板 / 多门 / 混合分区：那是**板件拓扑**的事（`dividers: []`、门 ≤ 2、抽屉只能整高区），要做就单独做；
- 开料套裁、标签包装、机床后处理全谱：不是这条线。

## 二、空间条目（`rooms[].spaces[]`，可选新字段）

| 字段 | 含义 | 缺省 |
| --- | --- | --- |
| `id` | 空间 id，**必须是合法 Python 标识符**（见 §三） | 必填 |
| `kind` | **柜类**，受控词表（`kitchen_base` / `wardrobe` / `sideboard`…）。求解器靠它取[工艺目录](craft-catalog.yaml)里的门宽、进深、踢脚、台面高；客户的说法由 LLM 映射到词表，**代码不猜词** | 必填（缺了取不到数字 → 停问） |
| `mode` | `wall`（靠墙一段）或 `free`（房间里一块地） | 必填 |
| `host_wall` / `offset_mm` | `mode=wall` 时的宿主墙与起端偏移（沿用今天墙摆的口径） | 墙摆必填 |
| `width_mm` | 这块空间的**净宽**（扣门洞、贴墙障碍、已摆家具） | 必填；`fill` 时由墙净长算出 |
| `depth_mm` / `height_mm` / `origin_z_mm` | 柜体进深、高度、离地 | 可省 → 取目录的常规值并标成助手假设；目录也没有就停问 |
| `constraints` | **约束**，不是结构：功能格清单（挂长衣 / 短衣 / 叠放 / 抽屉 / 被褥 / 大件）、通顶与否、开门方式偏好、收口与见光板 | 可省，按目录给候选 |
| `pinned` | 里面**钉住的单元 id**（客户点名/手动改过的） | 空 |

**关键：`spaces[]` 里没有"格数"和"每格宽度"。** 那是解，不是约束——客户的模糊想法只进 `constraints`。
**展开结果**就是 `rooms[].items[]`（今天的包络契约一个字不改）；**不存"空间 → 单元"的映射**，它由 §三 的确定性规则随时重算。

`fill: true` 是空间的一种特例（"把这条墙的空段铺满，没有别的约束"），保留兼容；内部转成一个 space 再求解。

## 三、单元身份与 id

**生成规则**：`{space_id}_u{n}`，`n` 从 1 起**单调递增、永不复用**。

- 在第 1、2 格之间插一格 → 新单元拿 `_u4`，其余三个 id 一个都不变（这就是"变更隔离"）；
- 显示顺序**不靠 id**：另存 `seq`（或用 footprint 排），id 与顺序解耦；
- 删掉的号**不回收**（回收就会让"新 u2"和"旧 u2"在继承判据里撞车）。

**⚠️ 已经踩到的坑（实测）**：下游 `panel_planning.cabinet_identity.admit_cabinet_id()` 要求 id 是**合法 Python 标识符且不含 `__`**；而**布局入口今天不校验**——

```
admit_cabinet_id(None, fallback="cabinet-1")  →  ValueError: cabinet_id must be a Python identifier
```

也就是说 `cabinet-1` 这种 id **能建项目、能过布局确认，到板件阶段才炸**（客户手上的工程正是 `cabinet-1`）。所以：

1. 生成规则用**下划线**（`north_run_u1`），不用连字符；
2. **布局入口已经补了集中校验**（2026-10-02）：`scene.parse_item_specs()` 在建项目/改布局时就拒，并说清为什么；只校验**输入**，读取照旧容忍（旧 id 靠一次性迁移改名）。**`space.id` 将来套同一条**（它生成单元 id，单元 id 就是板件阶段的 `cabinet_id`）——两边的规则一致性由 `test_skill_architecture` 钉住（阶段之间不互相 import，所以各写一条）。

**钉住的单元 id 必须稳定**：客户手动改过的那台，重解时不许被换掉或改名（否则"钉住"是假的）。

## 四、求解（确定性的那一段）

**输入**：一个空间条目 + 目录版本。**输出**：N 个单元包络（进 `items[]`）+ 每台的 `n_doors` 建议 + 功能标签 + 一句解释 + 代价提示。

求解顺序（照这个顺序写，别跳）：

1. **净尺寸**：`width_mm` 扣掉现场收口 / 见光板 / 障碍。**收口宽度是现场值**（量完墙再裁），目录只给"允许区间 + 扣减策略"（`edge.filler_allowance_mm` / `edge.filler_policy`）；这一排实际留多少走 `spaces[].constraints`，不是车间常量；
2. **先定门**：开门方式（平开 / 推拉 / 上翻）→ 门宽档 → **单元宽度上限**（1 门 ≤ 1 门扇上限，2 门 ≤ 2 门扇上限）；
3. **功能格**：从 `constraints` 推出功能格清单（挂长衣 / 短衣 / 叠放 / 抽屉 / 被褥 / 大件）；
4. **格数可行区间**：每个功能格取净宽下限 → 最少要几格；再由单元宽度上限得最多几格；
5. **选一个解**：优先**对称** → 优先**模数** → **余量集中在"调剂格"**（默认给**远端那一格**，即离起端锚最远的那格；它同时是"改动专责格"）；
6. **输出**：N 个单元 + 功能标签 + `n_doors` 建议 + 一句解释（"这格留 900 是为了放行李箱；两扇门各 448 是因为门扇上限 450"）+ **代价提示**（哪格偏窄、哪格够不着）；
7. **不可行就停问**，并给出可行区间——例如："2500 塞不下 3 格 × 800；能做到的是 2×800 + 1×850，或者 3 格各 800 但总宽要 2450"；
8. **确定性**：同一（空间，约束，**目录版本**）必须逐字节得到同一结果。目录版本**记进"来源"**（空间条目/单元上记 `catalog_version`，快照与交付清单能说"按哪一版工艺算的"），**但不进下游摘要**：继承判据看的是单元那五个字段，目录改了而几何逐字节相同 → 下游内容确实没变，不该失效。

## 五、钉住与重解

| 什么时候 | 怎么重解 |
| --- | --- |
| 空间尺寸变了（墙变宽、门挪位、`fill` 空段变） | 只重解**弹性**段；钉住的单元不动；**能不变的单元 id 与几何都不变** |
| 约束变了（加了挂长衣、要通顶） | 重解功能格 → 格数与格宽；同样尽量保持已有单元 |
| 目录变了（档位/门扇上限改了） | 重解全部弹性段（钉住的不动），并在摘要里体现 |
| 钉住的**放不下**了 | **停问**："你钉住的那台 900 放不进 2400 了，最短要 2500"——不静默挤压、不偷偷缩它 |
| 客户手动改了某台（拖了/改了宽/改了门数） | 那台**升格为钉住**，从此重解不再动它（客户的每次手改 = 一条新约束） |

## 六、与现有机制怎么接

- **`fill`**：`fill: true` → 内部转成 space（无约束）；[继承判据](../../cad-generated/references/revision-inheritance-design.md) 里那条 `fill` 例外改写为"派生宽度必变"；
- **继承**：`envelope_set` 判据不动（它看单元）；空间变化引起的单元增/删/改宽，按今天的 `added / removed / resized` 分类走；
- **确认**：布局检查点仍是"每间都审过"（[运行时契约](../../cad-generated/references/runtime-contract.md)），空间不单独设确认位；
- **决策台账**：拆分里的每个语义选择（几格、每格做什么、通不通顶）要么能指到一条 decision，要么显式标成助手假设——这就是[决策台账设计](../../cad-generated/references/decision-log-design.md)里那条"没有依据不许写"的闸门；
- **页面**：最小版＝单元照旧显示 + 空间做分组标签 + 钉住的那台有标记；"改空间只重解弹性段"的变化要看得见（哪些格子被重排了）；
- **契约**：`rooms[].spaces[]` 是可选新字段，旧的 `rooms[]`（只有 items）照旧工作。

## 七、数据目录（第一版骨架）

文件：`references/craft-catalog.yaml`（车间工艺数字的唯一真源，与 `sheet-stock-catalog.md` 同一习惯：**数据不是代码**，可被车间更新、被测试断言）。

**形态**：运行时可读的 YAML；另有一页 `references/craft-catalog.md` 只讲口径（谁维护、怎么改、改完要跑什么、缺项怎么办），**不复制数字**——两处状态迟早不同步。

**命名**：叫 `craft-catalog`（柜类工艺目录），不叫 `split-catalog`——它不只服务拆分（板件阶段也要读门宽/进深/踢脚/台面高），按第一个消费者命名会把归属提前钉死；名字要说"里面是什么"。**一个数据文件平放，一族数据文件才收进子目录**（`intake/` 是后者的形态）。

| 需要车间给的 | 现状（2026-10-02 首次给数） | 用途 |
| --- | --- | --- |
| 门扇宽度 | **已给**：兜底 300–450（上限硬、下限软）；厨房地柜 400–450、衣柜 300–450、餐边/玄关薄柜 350–400 | §四 第 2 步定单元上限 |
| 进深 | **已给**：衣柜 600、薄柜 350、厨房常规 600（允许 550–650）（外形含门） | §四 第 1 步 |
| 踢脚 / 台面 | **已给**：全局 50、厨房常规 100（上限 200）；厨房台面完成面 830、常用台面厚 15 → 柜体高 815 | 包络与板件参数 |
| 收口 | **已给 18–60**：宽度由**现场**定，目录只给允许区间 + 扣减策略（`reserve_max` / `reserve_typical`，待确认） | §四 第 1 步 |
| 标准单元宽档 | 待车间后期给 | §四 第 5 步取模数 |
| 各功能格最小净宽 | 待车间后期给 | §四 第 3–4 步 |
| 可达性高度带 | 待车间后期给 | 代价提示与默认分格 |

**代码只负责求解，不写"衣柜就该怎么分"。** 目录缺项时停问，不猜；非法值（负数、区间反了、档位不递增）在**加载时**就拒。

**版本怎么用**：目录带显式 `version`（车间改一次换一个），求解结果记下它是按哪一版算的（可追溯）；**不进下游摘要**（见 §四 第 8 步）。

## 八、边界（谁做判断）

- **LLM 做**：把客户的话整理成 `constraints`（"能装就行" → 挂衣为主、先按常规）、在候选之间推荐、解释代价、缺信息时追问；
- **代码做**：展开空间、求解格数格宽、钉住与重解、id 发号、几何与目录准入；
- **明确不进代码**：自然语言解析、按柜型猜默认分格、审美排序、替客户决定"要不要通顶"。

## 九、落地分批（每批都能单独验收）

1. **契约 + id + 展开器**：`rooms[].spaces[]` 字段与校验、id 规则、空间 → 单格直通（一个空间一台柜）；顺带补布局入口的 id 合法性校验。验收：老输入行为不变；插删一格不改别的 id。
2. **求解器 + 目录**：§四 的八步 + `craft-catalog.yaml`（**已建**，`version: draft-2026-10-02`）；不可行时的停问话术。验收：同输入逐字节同输出；不可行不会静默变形。
3. **`fill` 迁移**：`fill: true` 走 space 路径，继承例外改写。验收：一面 3000 的墙铺满得到 N 个合规单元（不再是一个 3000 宽的包络）。
4. **页面**：分组标签、钉住标记、重解影响面。验收：改空间时"哪几格被重排"看得见。

## 十、未决（要拍板）

1. **余量给哪一格**：本稿默认给**远端那一格**（远离起端锚）。若车间习惯"把余量留在靠墙那头"，改这一条即可。
2. **`group_id` 进不进第一版**：不进也能跑（整排一致性检查少一条）；进了就要定"整排检查失败怎么办"。
3. **一个空间能否跨两排**（L 形、转角）：**第一版不做**，转角拆成两个 space。
4. **目录谁维护、多久复核**：建议车间出一版初稿，之后改动走同一次评审。
5. **布局入口的 id 校验**：单独先修，还是跟批次 1 一起（建议单独先修——它今天就咬人）。
