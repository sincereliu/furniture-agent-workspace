# 页面写项目（设计稿）

这一页说清「页面上拖一件家具，项目里到底发生了什么」。契约细节见
[运行时契约](runtime-contract.md)「页面写项目」段；待评审与已知缺口登记在
[编排与生命周期未落地需求](backlog.md)；修订继承见 [修订继承设计](revision-inheritance-design.md)。

## 分水岭：页面能写项目了

在此之前，写项目只有一条路——对话（`furniture_revise_layout`）或确认流程；页面是**只读投影**。
现在多了一条：页面上改一件的摆放，**落成一个新 Revision**。

这是有意的：只读页能看不能改，用户每改一厘米都要回来找助手，反馈环太长。但"能写"必须付代价，
所以三条约束同时成立——**一次只改一件**（原子）、**必须带版本**（不许拿旧画面覆盖）、
**默认关闭**（灰度开关，没验证过就不开）。

## 为什么是「每次一个新 Revision」

- Revision 是这条流水线的审计单位：**历史不改写**。原地改最新 Revision 会让"已经确认过的内容"
  悄悄变样，`layout_sha256` 与冻结文件、下游 attempt 的血缘全跟着含糊。
- `revise()` 本来就干这件事：下游全部作废、父修订产物标 stale。页面改摆放与对话改摆放**是同一件事**，
  不该有第二套语义。
- 代价要认：连拖 20 次就是 20 个 Revision。真要治，方向是**同一次会话内的合并**
  （在最新 Revision 还没确认、还没有任何下游输出时原地改），属于后面的事，先不做——
  它会把"历史不改写"这条规则变复杂，得先有真实使用数据说明值得。

## 为什么改完就变成「未确认」

确认位是**人对某份内容点过头**的记号（`approved_stages` 的语义同此，见修订继承设计）。
改过的内容没人点头，所以新布局一律 `confirmed=False`，哪怕上一版是确认过的：

- 不继承确认位 = 不伪造审批。审计时"这一版是谁什么时候点头的"必须答得出来。
- 冻结文件只写已确认布局（`JsonProjectStore._write_frozen_layout`），所以新 Revision 不会留下
  `layouts/<新 sha>.json`——下游想读也读不到，只能先确认。
- 房间级确认（一次只确认改过的那间）是后面的事：先让"改了就回到未确认"这条简单规则跑起来。

## op 与几何：复用，不重写

op 词表、字段白名单、墙摆/自由摆放的互斥规则全部复用房间场景编辑（`scene_edit.apply_edit`）。
项目布局里每一间房本来就是一份 `RoomScene`，把它还原成"场景源"（`project_edit.room_scene_source`）就
能直接喂给同一个应用器——**不引入第二套字段判断**，也就不会出现"场景页允许、项目页拒绝"这种漂移。

改完必须重算：`plan_scene()` 重新摆放 + 准入校验，`footprint` / `clearances_mm` 是算出来的，
所以权威数据（`placement`）改了、派生数据不会留着上一版。校验不过就整体拒绝。

**`fill` 件是例外**：它的宽与偏移由墙上的空段反推（`placement.fill_span`），改完就被覆盖。
所以对 fill 件的摆放类 op 一律 422 说清原因——静默接受再丢掉是最坏的一种"成功"。
（改房间尺寸导致 fill 件变宽，那是房间编辑的事，不是摆放编辑。）

## 架构位置

HTTP 层不自己开 orchestrator（`test_entrypoint_architecture` 钉着这条）。页面写项目走
`furniture_workflow/project_layout_edit.py` 这个门面：它校验开关与版本、调
`furniture_layout/project_edit.py` 算几何、再驱动 orchestrator 造 Revision 并落盘。
几何在 layout 包、版本与生命周期在 workflow 包，两边都能单独测。

## 还没做（各自有归属）

- **页面接入**：预览页现在仍是只读（身份牌写着"由对话更新"）。让画布直接发这个 op 是"单页内核收敛"
  那一步的事——先有接口、先能灰度，再谈把拖动接上去。
- **同会话合并 Revision**：见上。要真实使用数据支撑。
- **对象锁**：同一间房两个人（或人和助手）同时改，现在靠 `expected_version` 挡住覆盖，
  但挡不住"轮流覆盖"。
- **房间级确认**：现在改一间要把整个布局重新确认。
- **外部只读分享**：见 [访问模式与外网分享](preview-access-design.md)（token 形态，尚未实现）。
